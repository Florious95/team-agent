# F7：会话身份、续作、克隆与分叉

## 一、用户获得什么

每个成员的上下文绑定稳定身份，可以跨停止、重启和 pane 更替继续；用户也能明确选择恢复、全新克隆或带上下文分叉，系统诚实区分已验证、尚待 backing、拒绝和 fresh。

用户可见承诺：

1. 会话归属必须唯一，不能用“同目录最新会话”绑定 sibling。
2. 恢复成功必须以停止前后的上下文连续为证，不以进程启动为证。
3. clone 产生独立新成员，不伪造上下文继承。
4. fork 产生不同且可核验的新会话，并承接源上下文；源会话保持不变。
5. backing 尚未形成时只能 pending；无法证明时 rejected；fresh 必须与恢复成功分开。
6. provider 不支持某项能力时明确披露，不静默降级。
7. **目录级身份槽对账（在途，锚 `10137cda`，未发版）**：启动 grok 席位前必须对账目录级 `<cwd>/.grok/config.toml`，把框架自己的每席键（`TEAM_AGENT_ID` / `TEAM_AGENT_OWNER_TEAM_ID` / `TEAM_AGENT_AUTH_MODE` 一族）清掉再启动，并写审计留痕（只出键名，不出键值）。清不掉（文件只读等）必须拒绝启动，不能带着脏身份开席。清单里没有的键不是“可以删”，是“不知道，所以不许动”。成因：grok 的 toml `env` 表与父进程环境合并，且同名键 toml 覆盖 env；光把身份放 pane env 不够。
8. **Pi 每席位隔离与 resume/reset（用户会签 2026-08-31）**：Team Agent 只增加协作所必需的每席位 MCP 身份和会话隔离。同一团队可以运行多个 Pi 席位，席位身份不得串位。restart/resume 只在持久 backing 存在且身份匹配时恢复原会话；缺失或不匹配时 fail-closed。start-agent reconstruction 与 resume 是不同语义，不得把重建冒充恢复。reset 丢弃旧会话并建立 fresh 会话，且不得影响 sibling 席位。条款地图 [[Pi provider 适配]]；Pi Provider 行为见 [[F3 Provider、模型、权限与资源组合]]。

准则锚：`docs/team-agent-foundation-and-boundaries.md` §7、§15；`docs/项目设计与定位备忘录.md` 二.3、三.5。

## 二、怎样黑盒判真

### 恢复连续性

原文锚：`docs/team-agent-restart-foundation-goal.md` §9.1、§9.2、§12。

1. 成员记住唯一标记，停止并恢复后必须答出标记。
2. session id、backing、agent identity 与 provider 均保持同属。
3. 缺 backing、foreign identity 或 collision 时拒绝，不能回退 latest。

### Clone 与 fork 区分

原文锚：基础边界 §15“恢复旧 agent / 基于 handoff 新开 agent”；restart goal §9 的上下文 round-trip。

1. clone 返回独立成员；首次 backing 未形成时诚实 pending-first-turn。
2. fork 返回独立 session/backing，并能回答源会话独有标记。
3. 连续 N 次 clone/fork，每个新身份与 backing 唯一，源成员不变。
4. 让 provider backing 延迟超过命令返回窗口：不得假 Verified，也不得把 fork 退化为 clone。

### 观察与归属分离

原文锚：基础边界 §7；restart goal §5 的 session capture/persist/resume；§8 的并发与超时测试。

1. 同 cwd 并发启动多个成员，观察器可给候选，但只有正向 identity 对齐者能入库。
2. 读/解析失败与 honest miss 必须可区分；二者都不能产出 foreign candidate。
3. 重启/compact 后重新核对 session/backing，不因旧 confidence 自动延续归属。

### grok 目录级身份槽对账（在途，锚 `10137cda`，未发版）

原文锚：用户裁定 2026-08-18（派单给定事实；本页不另测）。原则：清单外的键不是“可以删”，是“不知道，所以不许动”。

1. 在共享 cwd 的 toml 里预置另一席的 `TEAM_AGENT_ID`（及同族框架键）后启动本席：启动后本席身份不得变成预置的那一席；脏键必须已被清除，或启动被拒绝。
2. 启动成功后，审计留痕只含被处理的键名，不含键值。
3. 清单外的键（正控例：`GROK_FOLDER_TRUST`）启动前后仍在且值不变。
4. 将 toml 置为只读或其它无法清除的状态后启动：必须拒绝，不能带着未清除的框架键开席。
5. 同 cwd 两席先后启动，不得因 toml 残留而串台。

### Pi 每席位隔离与 resume/reset（用户会签 2026-08-31）

原文锚：`.team/artifacts/pi-provider-adaptation/requirements/pi-provider-requirement-final.md`。条款地图 [[Pi provider 适配]]。

1. Team Agent 只增加协作所必需的每席位 MCP 身份和会话隔离；不为 TeamMate Pi 建立独立的原生配置、认证或插件环境。
2. 同一团队可以运行多个 Pi 席位，席位身份不得串位。
3. restart/resume 只在持久 backing 存在且身份匹配时恢复原会话；缺失或不匹配时 fail-closed。
4. start-agent reconstruction 与 resume 是不同语义，不得把重建冒充恢复。
5. reset 丢弃旧会话并建立 fresh 会话，且不得影响 sibling 席位。
