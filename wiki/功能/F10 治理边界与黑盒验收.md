# F10：治理边界与黑盒验收

## 一、用户获得什么

用户获得的不是“测试很多”，而是每项产品承诺都有可重复的黑盒证明；失败、部分和未覆盖被诚实披露，测试不会污染用户环境，也不会通过改命令、弱化断言或复制实现语义制造假绿。

用户可见承诺：

1. 每个功能承诺都能追溯到准则、需求锚和黑盒判据。
2. 验收使用用户/leader 自然会走的 canonical 路径。
3. “通过”必须有真实执行证据；未跑、假 fixture、空洞负断言不能算绿。
4. 发布基线、候选和用户取得的发布物分别核验，不能互相替代。
5. 历史库存、并发和真实 provider 风险必须进入相应门，不只测干净环境 happy path。
6. 测试资源与真实 HOME、registry、socket、workspace 严格隔离。
7. 治理只约束如何证明产品，不成为用户需要学习的工作流。
8. 对“所有 public ingress 到 durable sink 必经同源 gate”这类结构权威承诺，产品提供机器可读 canonical manifest；验证和 CI 从该 SSOT 枚举，不能手抄入口、sink 或 gate。
9. **Pi/adapter 诊断信息与发布物 SHA 分离（用户会签 2026-08-31）**：Pi 与 adapter 的版本号、包版本和 digest 可以作为诊断信息。当所需协议与能力满足时，不得以精确版本或 digest 作为 Provider 准入门槛。本条不影响发布物自身的版本、SHA 和供应链完整性核验。不得把 adapter 诊断信息与发布物 SHA 核验混为一谈。条款地图 [[Pi provider 适配]]；Provider 准入见 [[F3 Provider、模型、权限与资源组合]]。

准则锚：`docs/team-agent-foundation-and-boundaries.md` §21–§22；所有 goal 的 In/Out of Scope、自动测试、真实验收、完成标准。

## 二、怎样黑盒判真

### 功能锚到 RED

1. 修复车先检索对应功能页，从“怎样黑盒判真”抽取红齿。
2. 在已发布基线真实证红，失败信号精确指向承诺缺口。
3. 候选转绿后再做反面齿、正控与邻接功能回归。
4. 找不到需求锚时标待补认，不从实现细节发明产品承诺。

### 防假绿

1. 负向断言同时证明请求真实进入系统并产生应有持久结果。
2. 枚举状态/矩阵从唯一权威目录派生，不在测试手抄第二份。
3. 真事故带历史库存时，升级门必须加载同型库存；fresh fixture 不得替代。
4. 并发风险按真实并发重复 N 次；单例成功不能洗掉竞态。
5. 合法输入正控必须成功，防止“全部拒绝”伪装安全。

### 发布闭环

原文锚：各 goal 完成标准均要求自动测试、真实验收、报告与未满足即 partial/blocked。

1. 对冻结候选依次验证契约、全量、真实平台/provider、升级库存、包 SHA/tag/CI、安装后自升级。
2. 每门记录命令、退出码、证据路径和未覆盖面。
3. CHANGELOG、版本号和用户可取得包与 tested SHA 一致。
4. Pi 与 adapter 的版本号、包版本和 digest 可以作为诊断信息；当所需协议与能力满足时，不得以精确版本或 digest 作为 Provider 准入门槛；本条不影响发布物自身的版本、SHA 和供应链完整性核验。（用户会签 2026-08-31）

### 结构权威与目录 ratchet

专项需求：[[结构权威清单与门覆盖]]。

1. 产品 manifest 申报 ingress/sink/gate 及 A/B/C；调用图验证 gate dominance；行为反证验证实际无旁路，三因子缺一不可。
2. 新 public ingress、durable sink、未知调用或 cfg-only 面未登记时 fail loud。
3. B 必须有 owner/退出计划；C 必须是闭集且有 reason/owner/canary；否则不得签 authority 通过。
4. manifest schema 版本化，未知 schema 拒绝；具体内部条目可随版本同片变化，不构成终端用户 API 稳定承诺。

## 三、现在处于什么状态

**0.5.57 时点：部分。**

已实现：

- 多层契约、异元审查、真实订阅、库存升级、CI/npm 与自升级已组成发布门。
- 0.5.57 首次把风暴历史库存纳入升级门，并证明 490 条 parked 原地不重播。
- 功能图现已提供需求锚→RED 的第一素材源。

仍未完整：

- 近期仍出现测试手抄状态目录、正控锚现状、干净环境漏历史库存、canary 分词假红等测试自身缺陷。
- `report_result` 证据归一化误伤说明验收证据的传递格式尚未单一。
- 产品尚无 canonical ingress/sink/gate manifest；结构 authority 的“申报”因子缺失，不能机器证明所有 public caller 链受同源 gate 支配。

对应架构：C8 全部契约门，并反查 C1–C7 的对外契约。
